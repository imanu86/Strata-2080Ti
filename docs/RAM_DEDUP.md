# RAM dedup: opt-in Windows arena prototype port

This port derives from FABLE commits cd7bdce, 0dc44cea, 01385d7 and 258e5ff. The original prototype was not compiled. Current checked port: GPT6.1. Default is OFF; `STRATA_RAM_DEDUP=1` enables it only for the anonymous normal-page Windows arena in `--serve --batch 0`. CUDA only; file/shared/large-page arenas, remote or peer expert tiers, foresight/lookahead and dynamic blob pinning are rejected. `STRATA_NO_LARGEPAGES=1` selects the eligible arena. Registration protection uses completed registration bytes, not the configured cap.

Only complete interior 4 KiB pages of experts with authoritative current GPU residency are decommitted. Shared edge pages and registered pages remain. Adaptive eviction queues a device-to-host copy while every victim remains GPU-resident, then drains and lands the recovered RAM before publishing any victim CPU-only. Every overwriting stream stays ordered after that copy. Prefill loans and physical tail/KV remaps restore missing CPU copies before reusing their GPU backing. There is no model-file fallback for an absent expert. CUDA or OS recovery failures are fatal; cleanup failures retain potentially reachable resources.

For this opt-in only, `blob_stable` returns a lease until the driver's checked full request-quiescence barrier. Default source-open lifetime remains unchanged when dedup is OFF. The barrier checks pending fills, loans, MTP chain and verifier work, waits commits and both parity/stage streams, then fences every participating device before reclaim. CPU expert work and prefill stagers finish before this boundary. No expert host pointer is retained in a captured graph. Reclaim is outside the native decode timer; D2H recovery during resize/adapt is included in runtime work.

The bounce ring defaults to 512 MiB (`STRATA_RAM_DEDUP_BOUNCE_MIB`, bounded 16–4096); `STRATA_RAM_DEDUP_KEEP_GIB` can retain a RAM quota of GPU-resident experts. The reported net estimate subtracts ring and allocated metadata from reclaimed interior bytes. This is not a working-set measurement. Ten GiB net savings and throughput are unqualified until measured. Adding PLE memory is a separate experiment and not enabled by this patch.

Qualification prepared: `ram_dedup_geometry_test` exercises the production geometry helper on CPU; `ram_dedup_cuda_test` exercises actual decommit/recommit, multi-device backing, repeated caller-stream ordering and byte comparison on a small synthetic arena. V3 tiny CUDA/Windows qualification passed 84 checks on both GPUs, including actual normal-page allocator admission. V3 model reached the first token with 16.27 GiB lower PrivateUsage than READY, then stalled: the preserved native dump places the main wait in InFlight landing/EventSynchronize, while the watchdog found two pipeline windows pending and the CPU pool completed/parked. Fatal Absent was logged after the dump during forced release; it is not an established cause of the initial stall. No complete 1024-token RAM request is qualified. V4 publication-order changes and the extended Present/drain test await their own build/CUDA and model qualification. Abstract state/fault tests in external work are contract models, not driver-fault coverage. Existing baseline VMM/stream and prefill cleanup limitations are not represented as repaired globally.

Admission checks the actual anonymous mapping (`mapping_base == base`, normal pages, coherent capacity and registered bounds); Windows also checks MEM_PRIVATE allocation at both ends. Ordinary release bookkeeping is not mistaken for a shared mapping. A checked sweep now runs after prompt refill and before REUSED/first token: its cost enters prompt_ms and TTFT, while the existing DONE sweep remains in final wall time. No 10GiB saving is claimed until measured.

The scratch V4 publish design also lands D2H recovery before prefill loans and wholesale cache/KV retirement; CUDA stream completion alone does not mark RAM Present. Waiting in a wholesale restore invoked by the service loop can still suspend service of another live stage: this ordering change does not claim a complete WDDM stall fix.

The reported D2H milliseconds are accumulated host wall time in evict/landing (API issue, event waits, recommit, memcpy and optional VirtualLock), not CUDA event duration or copy-engine time. Ring-full landing nested inside evict is included by both timers and can be counted twice. Do not sum this counter with native decode or interpret it as GPU D2H elapsed time.
